# Доступность и адаптивность (ветка 13-14)

Отчёт по пунктам задания. Все проверки выполнены на локальном сервере
`python -m http.server`, браузер Microsoft Edge (Chromium), Lighthouse 12.

## 1. Изображения и альтернативные описания

- Все `<img>` на сайте получают осмысленный `alt` с названием товара
  (формируется в `renderCard()` и `renderProductPage()` в `js/main.js`).
- Декоративные SVG-иконки помечены `aria-hidden="true"` и не попадают в
  дерево доступности.
- У всех изображений заданы `width="1000" height="750"` — браузер резервирует
  место, макет не «прыгает» при загрузке (CLS).
- Добавлены `loading="lazy"` (карточки каталога) и `decoding="async"`.

## 2. ARIA только там, где нужно

- Убрана избыточная разметка рейтинга: было
  `<p class="rating" aria-label="Оценка 5 из 5">★★★★★</p>` — `aria-label` на
  `<p>` без роли игнорируется, а звёзды зачитывались как «звёздочка» пять раз.
  Стало: звёзды скрыты (`aria-hidden="true"`), рядом текстовая альтернатива
  в `.visually-hidden`. Исправлено 9 блоков на `index.html` и `about.html`.
- `aria-label` оставлены только у элементов без видимого текста:
  кнопки с иконками («Наверх», «Закрыть», «Сменить тему»), переключатели
  языка и валюты, несколько `<nav>` (основная навигация, хлебные крошки,
  разделы в подвале).
- `aria-current="page"` — только на активном пункте меню.
- Порядок заголовков: в каталоге между `h1` («Каталог товаров») и `h3`
  карточек добавлен скрытый `h2` «Список товаров» — правило
  `heading-order` больше не нарушается.

## 3. Lighthouse-аудит доступности

Итог по всем шести страницам — **100 / 100** (категория Accessibility).

| Страница | Оценка |
|---|---|
| index.html | 100 |
| catalog.html | 100 |
| product.html | 100 |
| about.html | 100 |
| contacts.html | 100 |
| account.html | 100 |

Исправлено в ходе аудита:
- контраст текста: введены отдельные токены `--accent-text` (текст на фоне),
  `--accent-btn` (фон кнопок с белым текстом), `--success-text`;
  приглушённый `--muted` затемнён до 5.6:1, `--danger` — до 5.4:1;
- бренд в карточке и на странице товара — цвет категории, смешанный с `--ink`
  до доступного (5:1 и выше);
- бейджи «Хит», «В наличии», «Скидка» получили доступные цвета.

Контрасты тёмной темы проверены расчётом: текст 8.5:1, приглушённый 5.4:1,
розовый статус 7.4:1, белый на кнопке 5.5:1.

## 4. Сохранённые отчёты

Каталог `lighthouse/`:

- `a11y-index.html` — полный визуальный отчёт (открывается в браузере);
- `a11y-index.json`, `a11y-catalog.json`, `a11y-product.json`,
  `a11y-about.json`, `a11y-contacts.json`, `a11y-account.json` — машинные отчёты.

Перегенерация:

```bash
CHROME_PATH="C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe" \
npx lighthouse http://127.0.0.1:8642/index.html \
  --only-categories=accessibility --output=html --output=json \
  --chrome-flags="--headless=new"
```

## 5. Адаптивная вёрстка страниц

Проверены все шесть страниц на ширинах **320, 375, 768, 1024 и 1440 px** —
30 комбинаций, горизонтальной прокрутки и выходов элементов за экран нет.

Найденные и исправленные дефекты:
- 768–1024 px: навигация и кнопки шапки не помещались в одну строку и
  вылезали за экран (`scrollWidth` 1039 при ширине 753/1009). Правила
  переноса шапки (навигация отдельной строкой с горизонтальным скроллом,
  скрытие CTA) расширены с 720 до 1024 px.
- 320 px: плитки категорий и карточки могли раздвигать страницу — сетка
  переведена на `minmax(0, 1fr)`, плитки на узких экранах компактнее.

## 6. Responsive images

- Для каждого из 20 фото товаров сгенерированы варианты **400 px** и
  **700 px** в WebP (`images/products/<имя>-400.webp`, `-700.webp`).
- В разметку добавлены `srcset` (400w / 700w / 1000w) и `sizes`:
  карточки — `(max-width: 720px) 45vw, (max-width: 1024px) 30vw, 240px`,
  страница товара — `(max-width: 1024px) 92vw, 560px`.
- Проверено в браузере: при DPR 1 выбирается вариант 400w, при DPR 2 —
  700w, то есть на телефонах и ретине грузятся облегчённые файлы.

## 7. Адаптивные формы и таблицы

- Все поля формы заказа и входа: `label` связан через `for`/`id`,
  `inputmode="tel"` у телефона, телефон маскируется автоматически,
  шрифт полей на мобильных ≥ 16 px (iOS не зумит при фокусе,
  `.form-field__input { font-size: 16px }` в блоке `max-width: 720px`).
- Сетка форм (`form-grid`) на ≤ 720 px переходит в одну колонку.
- Диалог оформления заказа на узких экранах занимает почти всю ширину,
  получает внутренний скролл (`max-height` + `overflow-y: auto`).
- Табличных данных в проекте нет: характеристики выводятся списком
  `<dl class="spec-card__list">` с адаптивным поведением (flex-строка
  «характеристика — значение», переносится на узких экранах). Если таблица
  появится, для неё предусмотрен приём обёртки с `overflow-x: auto`.
